# ภาพประกอบรับสินค้า โซลาว

ชุดภาพต้นฉบับสร้างด้วยเครื่องมือ image generation ของ Codex สำหรับงานนี้โดยเฉพาะ ไม่มีภาพดาวน์โหลด สต็อก โลโก้ภายนอก หรือบุคคลจริง ออกแบบให้นึกถึงหน้าร้านอาหารและตลาดสดไทยตอนเช้า ด้วยลัง ตะกร้า ผัก กุ้ง ตาชั่ง และใบส่งของ

ใช้เส้น navy ปลายมน พื้น gold/cream และสีผิวอบอุ่น ภาพเป็น raster ที่มีลักษณะเส้นเดียวและพื้นสีเรียบ มีความแปรผันของเส้น/เฉดเล็กน้อยจากการสร้างภาพ ไม่ใช่ SVG ที่รับประกันเส้น 1.7 ทุกจุด ไอคอนเสริมเป็น SVG เส้น 1.7 จริง เข้ากับ `design/icons/receiving.svg` เขียวใช้เฉพาะเครื่องหมายสำเร็จ แดงใช้เตือนข้อผิดพลาด อำพันใช้ข้อสงสัยเกี่ยวกับภาพบิล ไม่มีข้อความอ่านได้ในภาพ ลายเซ็นเป็นเส้นสมมติ ไม่ใช่ลายเซ็นบุคคลจริง

ไฟล์ WebP ทั้ง 10 ภาพมีขนาด 480×480px พร้อม alpha สำหรับแสดงที่ 160–240 CSS px รองรับ 2x ที่ 240px ใช้ไฟล์เดียวทั้งสว่างและมืด มีพื้น cream เป็นส่วนหนึ่งขององค์ประกอบ ช่วยแยกเส้น navy จากพื้นมืด ไม่ต้องกลับสีด้วย filter ไม่ต้องโหลดภาพรุ่นมืดเพิ่ม ภาพเป็นภาพนิ่งทุกไฟล์

## สถานะและข้อความ

| ไฟล์ | ใช้เมื่อ | alt text ภาษาไทย | หัวข้อ / ข้อความประกอบที่เสนอ |
| --- | --- | --- | --- |
| `empty-today.webp` | โหลดข้อมูลสำเร็จแล้วแต่วันนี้ไม่มีเอกสาร | ลังรับของว่างและใบส่งของในยามเช้า | ยังไม่มีของเข้าวันนี้ / เริ่มจากถ่ายบิลใบแรก |
| `capture-bill.webp` | ก่อนเปิดกล้องหรือคำแนะนำถ่ายภาพ | สองมือประคองโทรศัพท์แนวนอนถ่ายใบส่งของบนโต๊ะข้างผักและตะกร้า | ถ่ายบิลให้ชัด / วางบิลราบ ให้เห็นครบทั้งใบ |
| `reading-bill.webp` | คำขอ OCR กำลังทำงานจริง | กรอบอ่านใบส่งของสามแถวข้างลังผักและตาชั่งตลาด | กำลังอ่านบิล / รอสักครู่ แล้วตรวจรายการอีกครั้ง |
| `review-lines.webp` | ขั้นตรวจผล OCR และจำนวนก่อนยืนยัน | มือชี้ตรวจจำนวนในใบส่งของข้างตะกร้าวัตถุดิบ | ตรวจรายการและจำนวน / ผลอ่านบิลเป็นข้อเสนอ แก้ไขได้ |
| `sign.webp` | ก่อนเปิดช่องเซ็นรับของ | พนักงานใช้ปากกาเซ็นใบส่งของข้างลังผัก | เซ็นรับของ / ตรวจชื่อผู้รับก่อนบันทึก |
| `received-success.webp` | เซิร์ฟเวอร์ตอบยืนยันรับของสำเร็จจริงแล้ว | ลังวัตถุดิบและใบส่งของพร้อมเครื่องหมายถูกสีเขียว | รับของเรียบร้อย |
| `offline.webp` | ขาดเน็ตและยืนยันได้ว่าร่างบันทึกในเครื่องแล้ว | เอกสารในมือถือพร้อมป้ายโทรศัพท์มีเครื่องหมายถูก และป้ายไวไฟขีดทับแยกกัน | ไม่มีเน็ต / ร่างนี้อยู่ในเครื่องแล้ว |
| `error.webp` | คำขอผิดพลาดและมีทางลองใหม่ | ใบส่งของพร้อมเครื่องหมายเตือนและลูกศรลองใหม่ | ลองใหม่อีกครั้ง / ถ้าระบบยังมีค่าที่กรอกอยู่ จึงบอกว่าเก็บรายการไว้แล้ว |
| `not-a-bill.webp` | ต้องการให้คนตรวจภาพที่ระบบสงสัยว่าเป็นสลิป | สลิปสั้นมีคิวอาร์เล็กเทียบกับใบส่งของยาวสามรายการ พร้อมคำถามอำพันหนึ่งจุด | ภาพนี้อาจไม่ใช่บิล / ถ่ายใบส่งของที่มีรายการสินค้า |

| `count-empty.webp` | ขั้นนับของใบไม่มีบิลที่ยังไม่ได้เพิ่มสินค้า (2026-10-24, r4) | ลังรับของเปิดอยู่ มีถุง กล่อง และผักวางข้าง กับมือถือคลิปบอร์ดเปล่า | ยังไม่มีรายการ |

ภาพและข้อความไม่ใช่หลักฐานว่าบันทึกในเครื่องหรือยืนยันบนเซิร์ฟเวอร์สำเร็จ ต้องผูกกับผลการทำงานจริง ห้ามใช้ภาพสำเร็จระหว่างรอคำตอบ และห้ามแสดง empty-today เมื่อโหลดล้มเหลว

## วิธีต่อเข้าหน้าจอในรอบถัดไป

รอบนี้เพิ่มเฉพาะ assets ยังไม่ได้เปลี่ยนหน้า component, route, CSS, API หรือ native project ตัวอย่างนี้เป็นแนวทางให้ Claude ใช้เมื่อได้รับคำสั่งเชื่อมต่อ:

```jsx
import emptyToday from '../../assets/illustrations/empty-today.webp';

// ตัวอย่างจาก client/src/pages/receiving/Receiving.jsx
// แสดงหลังโหลดสำเร็จและจำนวนเอกสารวันนี้เป็นศูนย์เท่านั้น
<div>
  <img
    src={emptyToday}
    width={480}
    height={480}
    style={{ display: 'block', width: 'min(100%, 240px)', height: 'auto', marginInline: 'auto' }}
    alt="ลังรับของว่างและใบส่งของในยามเช้า"
    decoding="async"
  />
  <h2>ยังไม่มีของเข้าวันนี้</h2>
  {/* ต่อปุ่มถ่ายบิลเดิม โดยคงการตรวจสิทธิ์และ handler เดิม */}
</div>
```

- ให้ภาพอยู่ก่อนหัวข้อ แต่ข้อมูลบิล/จำนวนและปุ่มทำงานต้องเด่นกว่า อย่าเพิ่มภาพขนาดใหญ่เหนือ ledger หรือทุกบรรทัดของบิล
- หากหัวข้อ/ข้อความบอกความหมายครบแล้ว ใช้ `alt=""` เพื่อไม่ให้โปรแกรมอ่านหน้าจอประกาศซ้ำ ตาราง alt ใช้เมื่อภาพให้ข้อมูลเพิ่มเติม
- Loading ใช้ข้อความ `role="status"` และ `aria-busy="true"` บนบริเวณงาน ระหว่างรอคำตอบจริง ภาพ reading-bill เป็นภาพนิ่ง ไม่ใช่ตัววัดเปอร์เซ็นต์ ใช้ spinner เดิมได้และเคารพ `prefers-reduced-motion` กับตัวเลือกของผู้ใช้
- Error ใช้ข้อความระบุสาเหตุและปุ่มลองใหม่จริง แยกออกจาก empty state; ระบุว่าเก็บข้อมูลไว้แล้วได้เฉพาะเมื่อยืนยันการเก็บได้
- Offline ไม่ใช้ภาพนี้อ้างว่ามี persistence ถ้ายังไม่มีระบบเก็บร่างจริง ให้เขียนข้อจำกัดตามสถานะจริง ไม่แสดงประโยค “ร่างนี้อยู่ในเครื่องแล้ว”
- รองรับ `.solao[data-theme]` และโหมด auto เดิม ภาพชุดนี้ไม่ต้องรู้ค่าธีม แต่ native splash มีไฟล์สว่าง/มืดแยกใน `../brand/`
- บนจอ 360–390px ใช้ขอบหน้าจอ 16px ตาม grid เดิม ภาพไม่เกิน 240px และไม่ดันปุ่มหลักพ้นโซนนิ้วโป้ง เว้นพื้นที่ safe area กับแถบ fixed เดิม
- ทดสอบต่อกับหน้าจอจริงทั้งสองธีม ขยายข้อความ 200% และ Android WebView ก่อนรวมงาน

## ไอคอนเสริม

`icons-extra/basket.svg`, `scale.svg`, `saved-local.svg` วาดใหม่ด้วย `viewBox="0 0 24 24"`, `stroke="currentColor"`, `stroke-width="1.7"`, `fill="none"`, ปลาย/มุมมน ใช้ 24px เป็นหลัก มี 20px ได้เมื่อพื้นที่จำกัด สืบทอดสีจาก semantic token เช่นเดียวกับไอคอนชุดเดิม

SVG ที่โหลดผ่าน `<img>` จะไม่รับ `currentColor` จาก parent ในหน้า ให้ต่อเป็น inline SVG/component หรือ sprite ในรอบรวมงาน แล้วกำหนด `aria-hidden="true"` เมื่อปุ่มมีชื่ออยู่แล้ว หากเป็นปุ่มไอคอนล้วนต้องมี accessible name และเป้าแตะอย่างน้อย 48px ไม่เพิ่ม basket/scale/saved-local เข้า registry เดิมในรอบนี้

## หลักฐาน

รอบ 2 สร้าง `offline` และ `not-a-bill` ใหม่ด้วย image generation; แก้ `capture-bill`, `reading-bill`, `welcome` จากภาพเดิมโดยลดเส้นย่อยในกระดาษ ผัก ลัง และตาชั่งให้อ่านที่ 160px ได้ใกล้ระดับ `error` และปรับพื้น cream รองรับขอบแขน/ผมที่สำคัญบนพื้นมืด ไม่มี glow ภาพอื่นและ SVG เสริมคงเดิม ป้ายเก็บในเครื่องอ้างรูปทรง `saved-local.svg` (โทรศัพท์ + เช็ก) ไม่ใช่ลูกศรดาวน์โหลด และ Wi-Fi ขาดแยกเป็นอีกป้าย

ใช้ `contact-sheet-light-r2.png` / `contact-sheet-dark-r2.png` และ `REPORT-r2.md` เป็นหลักฐานรอบล่าสุด ไม่ใช้ contact sheet รอบแรกตัดสินขนาดไอคอนหรือ splash การตรวจไฟล์สองรอบอยู่ใน `validation-r2-1.json` / `validation-r2-2.json` และรายการ checksum อยู่ใน `assets-manifest-r2.json` รายละเอียด prompt และรุ่นที่เลือกอยู่ใน `raw/r2/prompts-r2.json`

ต้นฉบับ 1254×1254px, prompt, รุ่นทดลอง, contact sheet สว่าง/มืด และรายงาน อยู่บน SSD ที่:

`/Volumes/SSD Files/SOLAO/market-order-system/reports/receiving-illustrations/`

ดูขนาดไฟล์จริงและ checksum ใน `assets-manifest.json` และผลตรวจสองรอบใน `validation-round-1.json` / `validation-round-2.json` ไม่ได้รัน server tests หรือยืนยัน UX บนเครื่อง Android ในงาน assets นี้

# สั่งของประจำวัน และ รับสินค้า (`ordering`, `receiving`)

> status: core · review: in-progress · อัปเดต: 2026-10-05

## หน้าที่
แผนกในสาขาเลือกสินค้าจากรายการ ใส่ตะกร้า แล้วส่งคำสั่งซื้อสำหรับวันที่ต้องการรับของ (ค่าเริ่มต้นคือพรุ่งนี้) แอดมินดูคำสั่งซื้อรวม และไปเดินซื้อของ เมื่อของมาถึง แผนกบันทึกจำนวนที่รับจริงในหน้ารับสินค้า ระบบจะบันทึกลงสต็อกให้

## Flow
1. `/order` (`ProductList.jsx`) เลือกวันที่และสินค้า → ตะกร้าเก็บใน `sessionStorage` (`CartContext.jsx`)
2. `/cart` → `POST /api/orders` สร้าง order สถานะ `submitted` ทันที → แจ้งเตือน LINE/Discord และกฎสั่งตรง
3. แก้/ลบด้วย `PUT` และ `DELETE /api/orders/:id` ได้เมื่อวันนั้นยังเปิดรับ และรายการยังไม่มีการซื้อหรือรับ
4. `/order/receive` → `GET /api/orders/receiving` (**GET นี้อาจรับของอัตโนมัติ** ดู ORD-06)
5. บันทึกรับของ `PUT /api/orders/receiving?scope=mine|branch` → `updateOrderItemReceivingWithInventory` เขียน `order_items.received_*` และ `inventory_transactions` / `inventory_balance` ตามส่วนต่างจากยอดเดิม
6. รับของที่ไม่ได้สั่ง `POST /api/orders/receiving/manual-item` จะสร้าง order item ใหม่แล้วรับทันที
7. รูปบิล `POST /api/orders/receiving/bill-photos` (จำกัด 500KB ต่อรูป)

## รับสินค้า
- `scope=mine` อัปเดตทีละ `order_item_id` ที่เป็นของผู้ใช้
- `scope=branch` รวมสินค้าเดียวกันทั้งสาขา แล้วแบ่งยอดรับตามสัดส่วนที่แต่ละแผนกสั่ง (`updateReceivingItemsBranch`)
- รับอัตโนมัติ: ตั้งแต่ 23:30 น. (เวลาไทย) รายการที่ค้างรับของวันก่อนหน้าจะถูกรับเต็มจำนวนที่สั่ง ยกเว้นกลุ่มที่บังคับรับเอง หรือสินค้าที่ `allow_pending_carryover`

## กติกา (ห้ามผิด)
- รักษา `order_items.id` เดิมตอนแก้ order เพราะการซื้อ การรับ รูปบิล และสต็อกอ้างอิง id นี้
- รายการที่ซื้อหรือรับแล้ว แก้ได้เฉพาะราคาและหมายเหตุ ห้ามลบ
- สต็อกเปลี่ยนตาม **ส่วนต่าง** `nextReceived - previousReceived` ถ้าบันทึกซ้ำด้วยค่าเดิมต้องได้ delta = 0
- วันที่สั่ง = วันที่ไปซื้อของ ปกติสั่งวันนี้ให้พรุ่งนี้ การเลือก "วันนี้" คือการสั่งของรอบเมื่อวาน (หน้า `/order` ขึ้นเตือนไว้)
- สั่งของได้จนกว่ารอบของวันนั้นจะปิด ลำดับการตัดสิน (`getOrderStatus`):
  1. แอดมินตั้งค่าไว้ (มีแถวใน `order_status_settings`) → ใช้ค่านั้นเสมอ แอดมินเปิดรอบเก่ากลับได้
  2. ไม่เคยตั้งค่า → เปิดรับถึงวันนั้น + `order_auto_close_grace_days` วัน (เวลาไทย, ค่าเริ่มต้น 0 = ปิดเมื่อพ้นวันนั้น, ค่าติดลบ = ไม่ปิดอัตโนมัติ) อ่านจาก `system_settings` โดยไม่เขียน DB
- ปิดอัตโนมัติไม่เปลี่ยน order จาก `submitted` เป็น `confirmed` เหมือนที่แอดมินกดปิด (`toggleOrderReceiving`) หน้าพิมพ์ใบผลิตที่ดึงเฉพาะ `confirmed` จึงยังต้องให้แอดมินกดปิดเหมือนเดิม
- วันที่ทางธุรกิจคือ **เวลาไทย** ให้ใช้ `toBangkokDateKey` ห้ามใช้ `toISOString().split('T')[0]` กับ "วันนี้"
- **ห้ามแก้ ORD-01 ด้วยการตั้ง `TZ=Asia/Bangkok`** เพราะ mysql2 คืนคอลัมน์ DATE เป็นเที่ยงคืนตาม TZ ของเครื่อง ทำให้ `toIsoDate` และ `getPreviousDate` ([order.model.js:2076](../../server/src/models/order.model.js)) เลื่อนไปหนึ่งวัน

## จุดเชื่อมระบบอื่น
- **line-bill-capture:** บิลในกลุ่ม LINE คือบิลของที่สั่ง จะเชื่อมโดยให้ฝั่งนี้เปิด API อ่านอย่างเดียว "ยอดรับจริงรายซัพพลายเออร์ต่อวัน" (มาจาก `order_items.received_quantity` × ราคา จัดกลุ่มตาม product group/supplier) ให้ line-bill ใช้เทียบยอดบิล สองระบบยังแยก DB กัน
- **inventory:** การรับของเขียน `inventory_transactions` ถ้าจะแยกโมดูลคลังออก ต้องตัดส่วนนี้ก่อน

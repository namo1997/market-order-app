## 3. ปรับโฟลว์การทำงาน

จากการไล่ดูจุดที่กดได้ทั้ง 46 จุดในหน้า admin แล้วหาว่าตรงไหนทำให้ผู้ใช้งง/ติดกับดัก

- ยุบปุ่ม `วิเคราะห์` + `จัดคู่ใหม่` เป็นเมนู **เครื่องมือ AI** ที่บอกขอบเขตในตัวเลือก
  (เดิม `จัดคู่ใหม่` ยิงทั้งฐานข้อมูลโดยไม่มี confirm และลอยอยู่บนหัวตลอด)
- ซ่อนช่องวันที่ 2 ช่องบนหัว (JS ยังใช้ค่าอยู่ แต่ผู้ใช้แตะไม่ได้แล้ว)

### ตัวเลขและความคืบหน้า
- **ป้าย AI นับความคืบหน้าสด** `AI อ่านแล้ว 39/50` พร้อมแถบ ถามซ้ำทุก 3 วิระหว่างมีคิว แล้วหยุดเอง
  อ่านครบแล้ว toast แจ้ง + รีเฟรชหน้าให้อัตโนมัติ
- **AI ปิดอยู่ → แสดง `AI ปิด · คิว N` และไม่ poll** ไม่แกล้งบอกว่ากำลังทำงานทั้งที่ไม่มีอะไรเดิน

## 4.7 วัดผลและสืบย้อน AI ได้แล้ว (ใหม่)

แนวคิดจากหนังสือ *Building Applications with AI Agents* (Michael Albada, O'Reilly)
ที่เน้น **evaluation + observability** เป็นสิ่งที่ตัดสินว่า agent อยู่รอดใน production ไหม

### วัดความแม่น — `npm run eval`

ระบบมี ground truth อยู่แล้วโดยไม่รู้ตัว: ทุกครั้งที่คนกดยืนยันคู่ แก้หมวด หรือเคลียร์ธงยอด
คือการบอกคำตอบที่ถูก ดึงออกมาเป็นชุดข้อสอบได้ฟรี

```
จับคู่ถูกใบ      94.9%   56/59  (ไม่เสนอคู่เลย 2)
หมวดหมู่ถูก       100%   7/7
อ่านยอดได้เอง    93.2%   55/59  (คนเข้าไปแก้ยอด 6 ใบ)
รวม 96%   ·   ในคู่ที่จับถูก 49/56 จะถูก auto-confirm
```

รันฟรี ไม่ยิง OpenAI (ใช้ `ai_result_json` ที่บันทึกไว้ + `scoreSequencePair` ตัวจริง)
`--min N` ใช้เป็นเกณฑ์ใน CI ได้ · ไม่มีชุดข้อสอบก็ข้ามอย่างสุภาพ ไม่ทำ CI แดง

**กับดักที่เจอ:** ตอนแรกวัดยอดเงินได้ 16.7% ซึ่งหลอกตา เพราะวัดจากชุด "รูปที่คนเข้ามาแก้ยอด"
ซึ่งคนจะแก้ก็ต่อเมื่อ AI ผิดอยู่แล้ว → เปลี่ยนเป็นวัดจากบิลทุกใบในคู่ที่คนยืนยัน

### สืบย้อน — `node scripts/ai-trace.mjs`

เดิมเวลา AI ตัดสินผิด **สืบไม่ได้เลย**ว่าตอนนั้นเห็นอะไร ตอนนี้บันทึก JSONL วันละไฟล์
ตอบได้ว่ารูปนี้ใช้ context อะไร กี่ token กี่วินาที ตัดสินว่าอะไร ด้วยความมั่นใจเท่าไร

ข้อมูลจริงจากการรันครั้งแรก: เวลากลาง 4.6s · p90 8.5s · **7,605 token/รูป**
และพบว่า `learning_examples` ที่ป้อนเข้า prompt = **0 เสมอ** ยืนยันว่ากลไกสอน AI ยังไม่เคยถูกใช้

### 4.8 ปลุกกลไกสอน AI ที่ตายมาตลอด

`ai_learning_examples` มีตาราง มีการป้อนเข้า prompt มาตั้งแต่ต้น แต่มี **0 แถว** เสมอ
เพราะเดิมผู้ใช้ต้องพิมพ์หมายเหตุเอง **แล้วยังต้องติ๊ก checkbox อีก** — แทบไม่มีใครทำ
(`ai-trace` ยืนยัน: `context.learning_examples = 0` ทุกครั้งที่เรียก)

เปลี่ยนเป็นถามเฉพาะตอน **แก้สิ่งที่ AI ทำผิด** ซึ่งเป็นจังหวะที่สัญญาณมีค่าที่สุด:

- กด **ไม่ใช่คู่นี้** หรือ **ยกเลิกการยืนยัน** → เปิดแผ่นถามสั้น ๆ *"AI จับคู่นี้ผิดเพราะอะไร?"*
- **6 เหตุผลสำเร็จรูป กดปุ่มเดียวจบ** (ยอดไม่ตรง · คนละร้าน · สลิปจ่ายบิลใบอื่น ·
  บิลยังไม่ได้จ่าย · เป็นเงินโอนเข้า · คนละกลุ่ม) เลือกได้หลายข้อ + พิมพ์เพิ่มได้
- เลือกเหตุผล = ตั้ง `ai_learning_approved` ให้อัตโนมัติ ไม่มี checkbox ให้ผู้ใช้เห็นอีก
- **ข้ามได้เสมอ** และการปฏิเสธยังทำงานปกติ — ไม่ขวางการแก้งานเพื่อเก็บข้อมูลสอน
- ตอน **ยืนยัน** ไม่ถามอะไรเลย เพราะการเพิ่มขั้นตอนในทางที่คนเดินบ่อยที่สุด
  คือสาเหตุที่ดีไซน์เดิมได้ 0 แถว

ทดสอบวงจรเต็มแล้ว: ปฏิเสธพร้อมเหตุผล → เกิดแถวใน `ai_learning_examples` →

แล้วคืนค่าข้อมูลทดสอบทั้งหมด

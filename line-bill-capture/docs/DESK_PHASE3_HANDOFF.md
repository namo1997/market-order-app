### B1 (สูง) โต๊ะเทียบ: กด Y/N ค้างแล้วยืนยัน/ปฏิเสธคู่ถัดไปเอง
- ที่: `public/desk-view.js` handler `document.addEventListener('keydown', …)` ท้ายไฟล์ (~บรรทัด 749–760)
- สาเหตุ: ไม่เช็ก `ev.repeat`; `run()` กันแค่ระหว่าง `busy` เมื่อ `update()` เสร็จ `draw(true)` วาดคู่ใหม่ทันที auto-repeat ครั้งถัดไปจึงคลิกปุ่มของคู่ที่ผู้ใช้ยังไม่เห็น
- แก้: `if (ev.repeat) return;` สำหรับคีย์ตัดสินใจ (y, n, s) และ cooldown ~400ms หลังเปลี่ยนงาน (`stage()`/`draw()` เปลี่ยน `cur`) ก่อนรับ Y/N อีก
- ตรวจด้วย: ส่ง keydown `{key:'y', repeat:true}` ต้องไม่มีการเรียก `update()`; Y ทันทีหลังเปลี่ยนคู่ (<400ms) ต้องไม่ทำงาน; Y ปกติยังยืนยันได้
- ตรวจ handler อื่นแบบเดียวกัน: `desktop-workspace.js` (J/K เลื่อนแถวได้ ไม่ต้องกัน), `glass-dock.js` ถ้ามีคีย์ตัดสินใจ

### เลย์เอาต์เป้าหมาย (ตามม็อกอัป)
1. **หัว**: ไอคอน + "ข้อมูลค่าใช้จ่าย" + บรรทัดย่อย (บิล/สลิป · ยอด · วันที่ · สาขา) | วงแหวนความพร้อม `x/N` | ↻ (`.expense-profile-reload` "โหลดฉบับล่าสุด") | ✕ (ปิดเดิม)
2. **ซ้าย ~400px**: แท็บ บิล/สลิป สลับรูปหลักฐานเดิม (`.expense-profile-evidence`, `.expense-profile-pair-slip`), แถบเทียบยอด บิล = สลิป + ป้าย "ยอดตรง/ต่าง",
   ข้อความแชทหลักฐาน, ปุ่ม "หลักฐานต้นฉบับ" (ปุ่ม "ดูหลักฐานต้นฉบับ" เดิม) และ "กลับไปดูแชท" (ปุ่มเดิม), สถานะหน้าบิล/หลักฐานเป็นป้ายสีส้มเล็ก
3. **ขวา เลื่อนที่เดียว**: แถบ "ใช้ข้อเสนอทั้งหมด" (ปุ่มเดิม) → ช่องจำเป็นเรียงเลข มีวง ✓ เขียวเมื่อครบ → ผู้รับเงิน (ไม่บังคับ) →
   disclosure "ข้อมูลเพิ่มเติม" (ใช้ disclosure เดิม ซึ่งเปิดเองเมื่อมีช่องจำเป็น/ข้อผิดพลาด) → disclosure "สินค้าจาก OCR" (วันรายการสั่ง + "เทียบกับสินค้าที่สั่งไว้" เดิม)
4. **แถบล่างคงที่**: ช่องบันทึกการตรวจ (textarea เดิมของ "เพิ่มบันทึกการตรวจ") | ข้อความสถานะ (`.expense-profile-state`) | ⓘ "เกี่ยวกับการบันทึก" (ย้ายเนื้อหาเดิมเป็น tooltip/ป๊อปโอเวอร์) | "บันทึกร่าง" | "บันทึกว่าตรวจข้อมูลแล้ว" (ปุ่มเขียว)

### กติกาการเชื่อมกับฟอร์มเดิม (สำคัญที่สุด)
- **ย้าย node เดิม ไม่ clone** (บทเรียนข้อ 14 ของ DESK_VIEW_HANDOFF: clone ทำให้ id ซ้ำและ hidden payload) ปุ่ม/ช่องเดิมทุกตัวต้องยังเป็น element เดิม handler เดิม
- **ชิปแทน `<select>`**: วาดชิปจาก `option` ของ select เดิม (อย่าคัดลอกรายการจาก `choices` เอง); กดชิป = ตั้ง `select.value` + `dispatchEvent(new Event('change',{bubbles:true}))`
  (และ `input` ถ้าฟอร์มฟังอยู่) ให้ `ExpenseProfileDrafts.set()` / validation / readiness ทำงานเดิม; ซ่อน select ด้วยคลาส ไม่ใช่ลบ; select ยังโฟกัสได้ด้วยคีย์บอร์ดผ่านชิป (ชิปเป็น `<button>` หรือ radio group พร้อม `aria-pressed`)
  - ฟิลด์: `transaction_type` (8), `expense_category` (11), `branch` (4), `supplier_payee_relation` (5, อยู่ใน "เพิ่มเติม")
  - ค่าที่ select เดิมเป็น disabled ชิปต้อง disabled ด้วย; เมื่อฟอร์มเดิมวาดใหม่ ให้วาดชิปใหม่จาก select ใหม่ (ใช้ลายเซ็นแบบ `sigOf` ใน `glass-dock.js` กันวน MutationObserver)
- **จำนวนช่องจำเป็นไม่ตายตัว**: ใช้ผลความพร้อมเดิม (`missing_fields` ของฟังก์ชัน readiness บรรทัดต้น `public/expense-profile.js`, และ `.expense-profile-required`) ห้ามเขียนกฎซ้ำ
  - ⚠️ ม็อกอัปแสดง 5/5 ตายตัว — **ผิดสำหรับบางรายการ**: `transaction_type` = `internal_transfer` / `loan` / `government_remittance` → `not_applicable` และ **ห้ามมีหมวด**
    (เซิร์ฟเวอร์ตอบ `expense_category_not_applicable`) #2335 ค่า กยศ น่าจะเป็น `government_remittance` → ต้องซ่อน/ปิดชิปหมวดและวงแหวนแสดง "ไม่ใช้กับรายการนี้" ตามข้อความเดิม
  - ช่องร้าน/ซัพพลายเออร์ แสดง/ซ่อนตามประเภทรายการด้วยตรรกะเดิม (ฟอร์มเดิมย้ายเข้าออก disclosure อยู่แล้ว — อย่าเขียนใหม่)
- **เดือน**: ฟอร์มเดิมมี `defaultPeriod()` ใส่เดือนจากวันที่ให้แล้ว (`.expense-profile-period-default`, `expenseProfilePeriodNotice`) — ใช้อันเดิม แสดงเป็นชิป 3 เดือน (ก่อน/ของวันที่/ถัดไป) + ปุ่มปฏิทินที่โฟกัส `<input type=month>` เดิม
  ตอนตรวจ preview #2335 ช่องเดือนว่าง ให้ตรวจว่า default ไม่ทำงานเพราะอะไร (อาจเพราะมีร่าง/revision แล้ว) ก่อนตัดสินใจ — อย่าเพิ่มการเติมค่าใหม่
- **ข้อเสนอ**: แสดงแค่ชั้นเดียวในกรอบเส้นประใต้ช่อง: ป้ายแหล่ง (แชท/กลุ่ม LINE/OCR สลิป) + ค่า + ปุ่ม "ใช้" (= ปุ่ม "ใช้ค่านี้" เดิม `.click()`) + ⓘ (= "ดูที่มา" เดิม) — ค่าที่แนะนำต้องให้ผู้ใช้กดเอง
- ปุ่ม "บันทึกว่าตรวจข้อมูลแล้ว": คง disabled/validation เดิม; ถ้าเดิมกดได้แต่ขึ้น error focus ช่อง ให้คงพฤติกรรมนั้น (อย่าเพิ่ม disabled ใหม่ที่ทำให้ผู้ใช้ไม่เห็นเหตุผล) — แสดง tooltip บอกช่องที่ขาด
- กฎเดิมที่ห้ามเสีย: optimistic revision/pair/invoice 409 → reload, ร่างค้างเมื่อสลับเอกสาร, beforeunload, กรอกได้หลังปิดรอบ (ข้อ 16), ไม่มี banner ล็อก

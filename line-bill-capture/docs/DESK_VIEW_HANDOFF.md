## 3. สิ่งที่ยังขาดเทียบกับม็อกอัป (งานของรอบนี้ เรียงตามลำดับที่ควรทำ)

ทำทีละข้อ ให้ผู้ใช้ดูแต่ละข้อก่อนไปข้อถัดไป (ผู้ใช้ปฏิเสธดีไซน์เร็ว ควรโชว์ไว)

### D1. ไฮไลท์ตัวเลข + เส้นเชื่อมระหว่างเอกสาร
- ใช้ผลจาก `glass-ocr.js` (กล่อง `.gl-ocr-box.amount` / `.ref` อยู่ใน `.gl-ocr` ที่ parent ของรูป) วาดเส้นโค้ง SVG
  จากยอดบนบิลไปยอดบนสลิป และจากเลขอ้างอิงถึงเลขอ้างอิง มีวงกลม ✓ (เขียว) หรือ ✕ (แดง) กลางเส้น — ดู `drawLines()` ในม็อกอัป
- ถ้าหากล่องไม่เจอฝั่งใดฝั่งหนึ่ง ไม่ต้องวาดเส้น และให้ fact ในแท่นบอกค่าแทน
- ให้ `glass-ocr.js` ส่ง event เช่น `window.dispatchEvent(new CustomEvent('lbc:ocr', {detail:{id, boxes}}))` หลังวาด แทนการให้โต๊ะเทียบเดา timing
- วาดเส้นใหม่เมื่อ resize / เปลี่ยนงาน / รูปโหลดเสร็จ ใช้ `ResizeObserver` ไม่ใช้ rAF loop

### D2. งานบิลไม่เข้าคู่ในโต๊ะเทียบ
- แสดงบิลซ้าย ช่องว่างเส้นประฝั่งสลิป คำถาม "บิลนี้จ่ายอย่างไร?" ปุ่ม: **หาสลิป** (`#selected-pick-slip`),
  **ขอโอน** (`#selected-request-transfer`), **เงินสด** (`#confirm-cash-payment`, ปุ่มเขียว) + ⋯ (แก้ยอดบิล `#selected-save-amount`,
  จ่ายรวมหลายใบ `#combine-unmatched`, ประเภทเอกสาร `#classify-*`, `#selected-not-document`, ตัวเลือก "แก้ปัญหารายการนี้")
- ก่อนกดต้อง `select()` รายการนั้นในมุมมองรายการ (ให้ปุ่มเดิมถูกสร้างใน `#reviewpanel`) แล้วค่อย `.click()` — แบบเดียวกับ `glass-dock.js`
- สลิปไม่เข้าคู่ทำแบบกลับด้าน: "สลิปนี้จ่ายบิลไหน?" ปุ่มหลัก **หาบิล** (`#selected-pick-bill`)

### D3. งาน "อื่น ๆ" / รูปที่ยังไม่รู้ประเภท
- รูปเดียวกลางจอ คำถาม "รูปนี้คืออะไร?" ปุ่ม: บิล / สลิป / เงินเข้า / ไม่เกี่ยว (`#classify-bill`, `#classify-slip`,

## 4. รายละเอียด `glass-ocr.js` ที่ต้องรู้

## 6. กับดักที่เจอแล้ว

- `function top()` ระดับ global ชนกับ `window.top` ทำให้สคริปต์ทั้งไฟล์ไม่ทำงาน — อย่าตั้งชื่อ global เป็น `top`, `name`, `status` ฯลฯ
- `S` ของหน้าเป็น `let`/`const` ระดับสคริปต์ อ่านจากไฟล์อื่นได้ แต่จาก devtools/eval ต้องใช้ `(0, eval)('S')`
- `requestAnimationFrame` และ `IntersectionObserver` ไม่ทำงานเมื่อแท็บถูกซ่อน (รวมถึงพรีวิวที่ไม่ได้แสดง) ใช้ `setTimeout`
- MutationObserver ที่สร้าง DOM ใหม่ทุกครั้งจะวนกับ `expense-status.js` (มันวาดหัวรายการใหม่เมื่อมีการเปลี่ยน) — ต้องสร้างใหม่เฉพาะเมื่อ
  "ลายเซ็น" ของปุ่มต้นทางเปลี่ยน (ดู `sigOf` + `uid` ใน `glass-dock.js`) และ observer ต้องรับ mutation แบบ attributes ด้วย
- CSS ของ `desktop-workspace.css` ใช้ `.day-workspace.dw-split #reviewpanel …` (3 class + id) กฎใหม่ต้องเจาะจงกว่า เช่นใส่ `#worklayout`
- รูปในพรีวิว 403: `.local-preview` เป็น symlink และ `storage_path` ชี้ไปชุดพรีวิวอื่น — วิธีแก้ที่ใช้แล้วอยู่ใน
  `/Volumes/SSD Files/SOLAO/line-bill-capture/tmp/copy-imgs.mjs` (มีรูปจริงแค่ ~224 รูป วันที่ 1–4 ต.ค. 2569)
- ข้อมูลพรีวิวเป็นสำเนาถึง 5 ต.ค.; `npm run preview:sync` ต้องใช้ `railway ssh` ซึ่งเครื่องนี้ยังไม่มีกุญแจ SSH
- ตรวจหน้าจอ: เครื่องมือพรีวิวย่อภาพมาก ใช้สคริปต์วัดขนาด/ตรวจล้น (`scrollWidth > clientWidth`) แทนการดูด้วยตาอย่างเดียว
- `node scripts/check-repository-hygiene.mjs` ล้มใน worktree เพราะ `.git` เป็นไฟล์ (ล้มแม้ไม่มีการแก้) — ไม่ใช่ปัญหาจากงานนี้

### P1. เปลือกโต๊ะ (nav + เมนูระบบ) — ทำก่อน เพราะทุกหน้าต้องใช้

- สถานะ AI (`#ai`) ผู้ใช้ขอเอาออกจากแถบบนแล้ว — อย่าเอากลับมาเป็นป้าย ให้อยู่เป็นบรรทัดเล็กในเมนู AI ได้

  ด้านบนเป็นการ์ด “ทำต่อจากตรงนี้” = วันที่ค้างเก่าสุดของแต่ละกลุ่ม พร้อมจำนวนค้างและปุ่มใหญ่ “เริ่มตรวจ” (คลิก `a.calendar-run` เดิมของวันนั้น)

  OCR ไฮไลท์ยอดในแต่ละใบ; เส้นเชื่อมจากชิปรวมฝั่งบิลไปชิปรวมฝั่งสลิป (ไม่ต้องลากทุกใบ)
- ปุ่ม: ยืนยันชุดนี้ (`#confirm-match-group`, disabled เมื่อยอดต่างตามเดิม), ไม่ใช่ชุดนี้ (`#reject-match-group`),
  ⋯ แก้ชุดเอกสาร (`#edit-match-group`), เสนอชุดที่ยอดรวมตรง (`#group-auto-match`), ล้างบิล/สลิป (`#clear-group-bills` / `#clear-group-slips`),
  สร้างชุดและรอตรวจ (`#save-match-group`)
- batch: ใบสรุปซ้าย, สลิปที่เลือกขวา, ปุ่ม เลือกสลิปที่ใกล้เคียง (`#batch-pick-slip`), เลือกหลายสลิป (`#batch-combine`)
- picker เลือกเอกสาร (`.candidate`, `#retry-picker-load`) ใช้ drawer เดิมได้ แต่ต้องลอยเหนือโต๊ะและอ่านง่าย

### P6. คืนเงินสำรองจ่าย (`reimbursement`)
- สลิปโอนให้พนักงานซ้าย, หลักฐานการซื้อจริงขวา (หรือช่องว่าง “ยังไม่มีใบเสร็จจากร้าน”)
- ปุ่ม: สร้างใบแทนใบเสร็จ (`#reimbursement-substitute`, หลัก), ใช้บิล/ใบเสร็จที่ยืนยันแล้ว (`#reimbursement-existing`),
  ไม่ต้องมีใบแทน (`#reimbursement-no-receipt`), ไม่ใช่ชุดเดียวกัน (`#reimbursement-reject`, แก้วตัวแดง); ฟอร์มใบแทนใช้ dialog เดิม (`#receipt-*`)

### P7. ถังเล็กที่เหลือ
- ขาดหน้ายอด (`orphan_page`): รูปหน้าที่ขาด + ปุ่ม เลือกบิลที่เกี่ยวข้อง (`#selected-pick-bill`); รูปอื่นที่ AI บอกว่าเป็นหน้าต่อ ใช้ทางเดียวกัน
  แทนการส่งไปรายการ ถ้าปุ่มเดิมรองรับ
- รอ AI อ่าน (`ai_pending`): การ์ดสถานะ (จำนวน, เวลา) + หยุดอ่านรอบนี้ (`#pause-ai`) — ไม่มีการตัดสินใจ
- ตกหล่น (`leftover`): รูป + ซ่อมสถานะรายการนี้ (`#selected-repair-state`); แสดงสถานะดิบเป็นภาษาไทย (เช่น `pending` → “รออ่าน”)
  เฉพาะการแสดงผลในโต๊ะ ห้ามแก้ค่าในข้อมูล
- ยังต้องมีทาง “เปิดในมุมมองรายการ” ใน ⋯ ของทุกงานเผื่อกรณีพิเศษ

### P8. หน้าต่างย่อยและ dialog ทั้งหมดบนโต๊ะ
- ตรวจว่าทุก dialog เดิมลอยเหนือโต๊ะ (z-index), อ่านง่ายทั้งสว่าง/มืด และปิดแล้วกลับมาที่งานเดิมในคิว:
  ถามเหตุผลตอนปฏิเสธ (`#why-*`), เปลี่ยนสลิป/เลือกเอกสาร, จ่ายเงินสด (`#cash-payment-*`, `.cashquicknote`, `.cashhistory-item`),
  ขอโอนเข้า LINE (`#transfer-request-*`), ใบแทน (`#receipt-*`), จัดเป็นอื่น ๆ (`#not-document-*`), พรีวิวสลิป (`#slip-preview-*`),
  ฟอร์มข้อมูลค่าใช้จ่าย (`expense-profile-*`), สรุปข้อมูลค่าใช้จ่าย (`#xs-*`, `.xs-cell`, `.xs-item`, `data-xs-open-day` — เปิดวันแล้วต้องอยู่ในโต๊ะ),
  ผู้ส่ง (`#refresh-senders`, `#close-senders`), ภาพเต็ม (`#chatlightbox-close`, ซูม `#chatzoom*`), ย้อนกลับหลังยืนยัน (`#undobutton`)
- ภาพเต็ม/lightbox ควรแสดงไฮไลท์ OCR ด้วย (ใช้ผลใน cache เดียวกัน)

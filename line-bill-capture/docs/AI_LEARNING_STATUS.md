# LINE Bill Capture AI learning status

เอกสารนี้เป็นจุดอ้างอิงกลางของบทบาทคนใน LINE, วิธีที่ระบบเรียนรู้, ตัวเลขคุณภาพ และข้อจำกัด
ตัวเลขด้านล่างเป็น production snapshot วันที่ **24 สิงหาคม 2569** ไม่ใช่ค่าที่คำนวณสด

## ระบบเรียนรู้อย่างไร

ระบบไม่ได้ fine-tune โมเดลภายนอก การเรียนรู้มีสามชั้น:

1. **กติกาถาวรใน prompt/โค้ด** เช่น ทิศทางเงิน รูปแบบเอกสาร บทบาทคน และลำดับ
   `ส่งรูป -> ผู้ส่งคนเดิมพิมพ์รายละเอียด`
2. **Owner-approved examples** จากการแก้ประเภทหรือบอกว่าคู่ถูก/ผิด ซึ่งนำกลับเข้า prompt
   เพื่อเป็นตัวอย่างประกอบการอ่านครั้งถัดไป
3. **Shadow AI audit** คาดการณ์ก่อนคนกด แล้วเปรียบเทียบกับคำตัดสินจริง แต่ไม่มีสิทธิ์แก้ข้อมูล
   ยืนยันคู่ ปิดรอบ ส่ง LINE หรือเพิ่มตัวอย่างเรียนรู้เอง

AI ทุกชั้นเป็นผู้ช่วยเสนอ คนยังต้องตรวจเอกสารและเป็นผู้ตัดสินสุดท้าย

ตั้งแต่ 25 สิงหาคม 2569 การตรวจคู่บน `/admin`, `/m2` และ `/m3` เก็บเหตุผลได้ด้วยปุ่มเดียว:

- ยืนยันคู่: เลือกเหตุผลคู่ถูก เช่น ยอดตรง ผู้รับสัมพันธ์กัน เลขอ้างอิงตรง หรือบริบทแชทยืนยัน
- ปฏิเสธ/ถอนคู่: เลือกเหตุผลคู่ผิด เช่น ยอดไม่ตรง คนละร้าน สลิปจ่ายบิลอื่น หรือเป็นเงินโอนเข้า
- การกดเหตุผลถือเป็นการอนุมัติตัวอย่างเรียนรู้ทันที ไม่ต้องติ๊กช่องซ้ำ
- `เหตุผลอื่น` และข้อความเฉพาะกรณียังคงต้องให้คนพิมพ์และยืนยันเอง
- หลักฐานแชทเลือกเพิ่มก่อนกดเหตุผลได้ แต่ไม่มีสิทธิ์ยืนยันงานแทนคน
- ข้อความแรกของผู้ส่งคนเดิมหลังรูปกำหนดทั้งยอดและชื่อรายการแบบ deterministic;
  ข้อความก่อนรูปใช้ได้เฉพาะกรณีไม่มีรายละเอียดหลังรูปและหลักฐานในภาพสอดคล้องกัน
- รูปหลายใบที่ผู้ส่งคนเดียวกันส่งติดกันก่อนข้อความรายละเอียดถือเป็นชุดเดียวกัน รูปเลขบัญชีหรือรูปประกอบ
  จึงไม่ทำให้บิลใบแรกย้อนกลับไปยืมชื่อรายการจากข้อความก่อนหน้า
- ก่อนเลือกบริบท worker ต้องรวม pseudo user จากไฟล์ LINE export เข้ากับ canonical LINE user ID มิฉะนั้น
  รูปและข้อความของคนเดียวกันอาจถูกกรองออกว่าเป็นคนละผู้ส่ง

## ข้อจำกัดที่ต้องจำ

- Worker โหลดตัวอย่างเข้าแต่ละ prompt สูงสุด 12 รายการจากทั้งหมด 30 รายการ โดยจัดจากความใหม่/ความพร้อม
  ยังไม่มี retrieval ตามความใกล้เคียงของสาขา คน ร้าน ประเภท หรือรูปแบบเอกสาร
- กติกาบทบาทและกติกาแชทใหม่มีผลกับรูปใหม่หรือรูปที่สั่งอ่านใหม่ รายการเก่าที่คนตรวจแล้วไม่ถูกแก้เงียบ ๆ
- มี decision 139 รายการ แต่แนบหลักฐานแชทแบบ snapshot เพียง 2 รายการ และมีเหตุผลข้อความ 50 รายการ
  ข้อมูลฝึกเหตุผลเชิงเอกสารจึงยังบาง
- Pending match 220 แถวอาจรวมหลาย edge ของธุรกรรมหลายบิล/หลายสลิป ห้ามตีความเป็น 220 ธุรกรรมโดยตรง
- คะแนน confidence ของโมเดลไม่ใช่ความแม่นยำที่วัดจาก ground truth

## ลำดับปรับปรุงถัดไป

1. ทำ relevance retrieval ให้เลือกตัวอย่างตามประเภทเอกสาร คน สาขา ร้าน และคำสำคัญ แทน latest 12
2. ติดตามสัดส่วนและคุณภาพตัวอย่างคู่ถูกที่ได้จากปุ่มเหตุผลใหม่ แยกตามสาขาและประเภทเอกสาร
3. เพิ่มหลักฐานแชท snapshot ในการตัดสินใจเสี่ยงสูง โดยเฉพาะแก้ยอด เปลี่ยนคู่ และสำรองจ่าย
4. วัด Shadow แยกตาม action key และสาขา ก่อนพิจารณาเปิดเป็น assist mode
5. สร้าง eval set จาก human-reviewed records แล้วรันก่อนและหลังเปลี่ยน prompt ทุกครั้ง

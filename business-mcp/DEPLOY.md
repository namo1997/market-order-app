# Railway release procedure

This plan has two production changes: General Cashflow's read-only token policy, then a new `business-mcp` service. Both require the user's release approval under the workspace `AGENTS.md`. The Gateway cannot be declared connected until all four reads pass with real credentials.

1. Confirm the committed source and review the diff. Preserve the current Cashflow primary `CASHFLOW_DOT_*` settings and its installed ChatGPT connector. Generate a distinct long random bearer for Gateway; put only its SHA-256, branch allowlist and expiry in `CASHFLOW_DOT_EXTRA_TOKENS_JSON` on the Cashflow service. Put the raw value only in Gateway's `CASHFLOW_DOT_BEARER` secret. Release Cashflow source with the existing service workflow, then prove the old connector and new token both work and that other branches are denied.
2. In HRMS, add or provision two `MCP_SCOPED_TOKENS` entries, one for `BR02` and one for `BR03`, with person/salary/leave-reason permissions off. Put those raw tokens only in Gateway's `HRMS_MCP_TOKENS_JSON`. Verify `hrms_overview` returns `policy.branch_scope` equal to the mapped HRMS ID for each branch.
3. Confirm LINE Bill's Production `LINE_BILL_CAPTURE_GROUP_LABELS` source IDs before using the example mapping. Bind Gateway's `LINE_BILL_EXPORT_BEARER` to the existing read-only accounting export token through Railway secret/reference configuration. Do not fetch images or raw transactions for the Gateway.
4. Create one new Railway service rooted at `/business-mcp` using its Dockerfile and 1 replica, without a database/volume. Set `MARKET_ORDER_BASE_URL`, `HRMS_MCP_URL`, `CASHFLOW_BASE_URL`, `LINE_BILL_BASE_URL`, `BUSINESS_BRANCH_MAP_JSON`, `BUSINESS_MCP_CLIENTS_JSON` and the source bindings above. Set `BUSINESS_PUBLIC_URL` to the new HTTPS domain; generate and store `BUSINESS_OAUTH_SIGNING_KEY` and the SHA-256 of a separate strong owner login secret. Set `BUSINESS_OAUTH_CLIENT_NAME` to the owner policy name. Do not log or expose secret values.
5. After each approved deployment, wait for Railway `SUCCESS` and verify runtime source hash/commit per workspace release rules. Run `npm run verify:live` with `BUSINESS_VERIFY_CLIENT` to check real reads from Market Order, HRMS, Cashflow and LINE Bill. Record only per-source status and coverage in an SSD report. `PARTIAL` from source pagination is not a connectivity failure, but must remain visible to the AI.
6. Test authenticated MCP `initialize`, `tools/list`, overview and an authorized detail call; test out-of-scope branch/date/person denial. Test OAuth discovery, DCR, PKCE, token refresh and one real ChatGPT plugin read. Only then describe the Gateway as online. Push/reconcile the released commit and production-base branch following the workspace rule.
